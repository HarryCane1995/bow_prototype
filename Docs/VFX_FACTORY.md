## Open and export

Run the existing WebLab server: `python Tools/Art/FacadeFactory/WebLab/server.py`.
Open `http://127.0.0.1:8765/?tab=vfx&vfx=MESH_EXPLOSION_3D`, or choose
**VFX → VFX MODE → MESH_EXPLOSION_3D**. The separate **PSX_EXPLOSION** sprite
prototype remains available. **SURFACE** retains the facade/surface workflow.

**EXPORT MESH EFFECT** writes a complete, versioned directory under
`Assets/VFX/Explosions/MeshExplosion3D/<name>/`. Existing names receive `_r02`,
`_r03`, etc. Example: `mesh_explosion_99/review.tscn`.

The current mesh pipeline is fully local: Python/Numpy generates triangles and
seeded animation descriptors, Three.js previews them, and Godot imports the OBJ
meshes. There are no sprite textures or camera-facing geometry in this mode.
The editable source is the `.meshvfx.json` recipe plus the procedural generator.
These new procedural effects have no `.blend` source; this does not alter the
existing Blender-first pipeline for Level_01 or character assets.

## Layers and functioning controls

- Global: seed/randomize, scale, duration.
- Core: size, brightness, lifetime; a faceted star/blob mesh.
- Petals/fire: count, length, width, curl, spread, irregularity, lifetime;
  curved double-sided mesh shells, distributed radially in 3D.
- Ring: enable, radius, thickness, expansion speed, tilt and height;
  a triangulated band in the ground plane before tilt.
- Shards: enable, count, length, spread and speed; solid tetrahedral spikes
  with independent outward trajectories and rotation.
- Smoke: enable, count, puff size, expansion speed, opacity, darkness,
  delay and linger; individual faceted icosphere-derived clumps.
- Ground puff: optional low, flattened cloud meshes, with spread control.
- Retro: low-poly density, vertex wobble, stepped lighting, color quantization,
  Bayer transparency strength, chunkiness and silhouette exaggeration.

Each layer has enable, **Color A/B**, opacity, emission, **Alpha / Dither /
Additive**, fade curve, soft gradient alpha, unshaded shading, depth-write and
backface-culling settings. The opacity/color controls live inside the layer's
section; less common render settings are under **Material response**.
Selecting Dither initially enables depth writing; the checkbox can override it.
At zero dither strength, Dither mode becomes fixed-threshold alpha scissor.

The duration is the clip boundary. Individual starts/lifetimes are clamped to
fit inside it. Increase global duration to allow a longer smoke linger.
Disabling a layer or changing its material does not reshuffle geometry or seed
descriptors. Low-poly density changes in discrete subdivision/segment steps.

## Preview and runtime

Play/pause/restart, loop, time scrub, orbit and zoom. Camera presets: free orbit,
side, top, gameplay distance. Backgrounds: in-game dark with a floor and a 1 m
reference cube, black, neutral gray. Parameter edits preserve the paused time
for inspection; randomizing the seed starts the new variation at time zero.

The exported directory contains:

- `meshes/*.obj`: actual triangle geometry, with flat normals and UVs.
- `materials/*.tres` and `*.gdshader`: six separate material resources.
- `explosion.tscn`: reusable effect root, layer groups and child meshes.
- `player.gd`: analytic growth, translation, spin, opacity and emission-like
  fade. Methods: `restart()`, `seek(seconds)`; signal: `finished`. One-shot by
  default, optional loop. Per-instance shader parameters isolate copies.
- `manifest.json`: mesh animation descriptors, recipe, duration and statistics.
- `<name>.meshvfx.json`: effective parameters, seed, layer settings, generator
  fingerprint and SHA-256 of every mesh.
- `review.tscn`, `review.gd`: isolated Godot stage. Drag to orbit; wheel to zoom;
  R restarts, Space pauses; side/top/gameplay buttons change camera.
- `README.txt`: usage and source contract.

Reload with **LOAD RECIPE**. **SAVE MESH RECIPE** downloads a versioned recipe
without exporting runtime assets. Preview and export use the same mesh builder
and analytic animation formula; camera movement never changes mesh transforms.
Godot import sidecars are generated by Godot, not edited by the exporter.

The shader render modes and instance parameters use the
[Godot 4.6 spatial shader API](https://docs.godotengine.org/en/4.6/tutorials/shaders/shader_reference/spatial_shader.html).

## Validation and limits

`python Tools/Art/VFXFactory/qa_mesh_vfx.py` checks deterministic geometry,
finite triangles/normals, true three-dimensional extents, material/toggle
isolation, recipe reproduction and non-overwriting export. The initial default
has **35 active meshes / 978 triangles**, plus 7 disabled dust meshes.

Godot 4.6.3 Forward+ GPU validation:

```powershell
godot --headless --editor --path . --import --quit
godot --path . --script res://Tools/Rendering/verify_mesh_explosion.gd -- --capture
```

The runtime check verifies mesh/material loading, playback, pause, one-shot
completion, per-instance state, and camera-independent mesh transforms. GPU
captures: `.godot/mesh-vfx-review/{top,side,gameplay,smoke}.png`.
The same checks passed on the exported `mesh_explosion_99` in Godot 4.6.3,
D3D12 Forward+, RTX 5060. Browser console had no WebGL errors. Surface's three
generation modes and its existing favorite thumbnails remain functional.

Limitations: this is one archetype, not a particle editor or fluid simulation.
Alpha/additive shells can expose ordinary transparency sorting at overlaps;
Dither with depth writing offers a different look. Lighting is intentionally
simple and posterized. Emission affects the mesh appearance, without dynamic
lights or bloom. Browser and Godot tone/display processing can differ. Godot
Forward+ was tested; Mobile/Compatibility were not. Lifetimes are bounded by
global duration. No collision, sound, gameplay triggers, character integration
or automatic asset relocation is included. Keep each exported folder at its
saved `res://` path or update its resource references when moving it.

## Level_01 cyborg death integration (subsequent pass)

`Scenes/Enemies/CyborgPressureEnemy.tscn` now assigns the user's exported
`MeshExplosion3D/mesh_explosion_99_r02/explosion.tscn` as **Death Effect Scene**.
All eight Level_01 cyborgs inherit this assignment. The exported recipe, meshes,
materials and player script remain unchanged.

The pressure proxy previously had no damage/death handler. Its existing C#
script now implements the project's `IDamageable` contract, so the unchanged
`ArrowProjectile` hit path triggers death. **Max Health** defaults to 8 (one
ordinary 8-damage arrow). Nonlethal damage does not play the effect; repeated
hits after death cannot create duplicates. Inspector **Death VFX** also exposes
**Death Effect Scale** and **Death Effect Offset**.

Death stops shooting and hides the cyborg immediately. Deferred completion
spawns the effect under the current level, upright at the cyborg's world origin
(feet), so the shock ring stays at ground/platform height. The enemy is removed;
the one-shot effect remains for its exported duration and frees itself on
`finished`. Level unload also removes active effects. This is visual feedback,
without blast damage, sound, or changes to player/movement/character systems.

Validation: `dotnet build --no-restore`; Godot 4.6.3 headless and Forward+ runtime
checks using `Tools/Rendering/verify_cyborg_death_vfx.gd` (`-- --capture` for the
GPU view). Checks include a real production-arrow collision in Level_01,
nonlethal damage, duplicate hits, simultaneous deaths, elevated placement,
automatic cleanup, an empty effect field, and reloading the level. Runtime
reports and the capture are under `.godot/cyborg-death-vfx/`. The pre-existing
legacy viewmodel aim-reference warning still appears when loading the player.

### Gameplay-camera visibility fix

The first integration capture used a detached review camera and missed a
render-order bug on the real player camera. `StylizedContactDarkening` used
render priority 127, so its full-screen `screen_texture` composite overwrote
the transparent explosion. Godot's 3D screen texture only contains the opaque
pass ([screen-reading shader documentation](https://docs.godotengine.org/en/stable/tutorials/shaders/screen-reading_shaders.html#behind-the-scenes)).

`Scenes/Rendering/StylizedContactDarkening.tscn` now runs that composite at
priority -128, before transparent world effects. Its shader, strength, depth
response and the exported explosion remain unchanged.

Added `Tools/Rendering/verify_cyborg_vfx_visibility.gd`: a Forward+ pixel check
on the actual `Player/CameraPivot/CameraEffectsPivot/Camera3D`, with its existing
post-processing attached. The fixture moves to an unobstructed firing position;
it does not modify saved player settings. Before the fix the effect changed
0 pixels with post-processing enabled versus 5706 when disabled. After the fix:
5707 versus 5706, and 8/8 sampled realtime animation frames visibly contain the
effect. No pause/seek is used for that realtime replay. Reports and captures:
`.godot/cyborg-vfx-visibility/`, with pre-fix evidence in `before/`.

### Authoring and browser library

- **RANDOMIZE SEED** changes deterministic spatial variation.
- **VARY WITHIN PRESET** starts from the selected archetype's shape values and
  varies them within 20%, bounded by each control's legal range; it preserves
  authored material edits.
- **RECIPE LIBRARY** has ten curated thumbnail presets. **SAVE TO LIBRARY**
  stores up to 12 user recipes and compact WebP screenshots in this browser's
  local storage. Browser favorites are not production exports or a shared
  filesystem database. Download JSON or export the effect for portable storage.
- **SAVE MESH RECIPE** and **LOAD RECIPE** round-trip the effective parameters.
  Generator 0.2 accepts original 0.1 explosion recipes and reproduces their OBJ
  SHA-256 exactly. Already exported gameplay assets are never regenerated.
- New exports use `Assets/ProceduralArt/VFX/<name>/` with non-overwriting
  revisions. Existing `Assets/VFX/Explosions/...` production exports are untouched.
- The shape section precedes layer materials. Irrelevant explosion sliders are
  hidden on other archetypes. Material controls stay separate from geometry.

Directional conventions: **trail wake extends along local -Z**; the laser
arrives from **local +Z** at the impact center; lightning descends from **+Y**.
Rotate the effect root to orient it. The projectile streak is a finite authored
wake, not a persistent trail recorder following arbitrary projectile history.
Duration is the clip boundary; element lifetime/stagger is clamped to it.

### Storage and verification

`python Tools/Art/VFXFactory/build_library.py` exports the curated matrix and
refuses to overwrite existing names. Normal WebLab export creates a revision.
The mesh backend checks the shared 15 GiB hard reserve before writes; below
25 GiB it reduces retained preview cache entries to 8, otherwise it keeps 24.
It removes only its own content-addressed JSON preview files. The library
contains no movie, frame sequence, large packed image, or duplicate production
revision.

`python Tools/Art/VFXFactory/qa_mesh_vfx.py` validates all ten distinct topology
fingerprints, finite triangles/unit normals, timing bounds, seed/recipe
reproduction, material/toggle isolation, every exposed family shape control,
legacy 0.1 mesh hashes, and non-overwriting export. Node syntax checks cover
both mesh UI modules.

Runtime verification after Godot import:

```powershell
godot --headless --editor --path . --import --quit
godot --path . --script res://Tools/Rendering/verify_vfx_library.gd -- --capture
```

The isolated verification loads all ten actual exported reviews, checks OBJ and
shader resources, realtime progress, pause/seek, active fade uniforms,
camera-independent transforms, separate instances, end visibility, one-shot
completion exactly once, and looping. It writes ten 960x640 GPU frames plus
`runtime_report.json` under `.godot/art-pass-vfx-review/`. Consult that report
for the verified runtime result; successful geometry tests alone do not prove
GPU rendering. No player, movement, map or gameplay integration is added.

Known limits: transparent geometry has normal sorting/overdraw tradeoffs;
smoke is stylized polygonal alpha geometry, not a volume simulation; light
emission does not cast dynamic lights. Spatial width is authored in metres,
so fine electricity may need larger widths at long gameplay distances.
The browser and Godot use their respective display pipelines. Only the
existing project's Forward+ runtime is the intended target for this pass.
